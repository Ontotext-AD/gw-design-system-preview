Overview

Dialogs interrupt the current flow to request information, confirmation, or a decision. Use them for focused tasks that require immediate user attention.

  • PrimeNG component: Dialog
  • Import: import { DialogModule } from 'primeng/dialog';
  • Selector: p-dialog

Usage

Use when

  • You need a focused interruption for a single decision or form task.
  • The user must confirm, provide, or review a short amount of information.

Do not use when

  • A full page is a better place for the task.
  • A drawer, popover, inline validation, or message can communicate the state more lightly.
  • The flow requires multiple steps or long-form content.

Use dialogs for short, focused tasks.

When content grows, internal scrolling keeps the overlay usable.

Avoid placing full workflows inside a dialog. Long forms, multi-step tasks, and dense reference material usually belong on a page or in a drawer.

This example keeps the dialog open while users read more content, but the layout remains bounded and scrollable inside the component.

Background scroll is blocked while the modal dialog is open.

Use the maximize button in the header to expand the dialog within the viewport.

Maximize is supported by the installed PrimeNG Dialog.

Restore closes the maximized state and returns the dialog to its previous size.

The dialog uses the installed breakpoints input so it stays readable on tablet and mobile widths.

Size

  • Prefer content-driven widths and keep dialogs narrow enough to scan quickly.
  • Use sensible min/max widths so content does not stretch unnecessarily.
  • Avoid full-screen dialogs unless the task genuinely requires it.
  • On mobile, use responsive widths so the overlay remains usable without forcing a desktop layout.

Content Guidelines

  • Keep titles short and specific.
  • Keep the dialog focused on one task.
  • Use clear action labels rather than generic labels such as "Yes".
  • Avoid large amounts of content.
  • Avoid complex multi-step flows inside a dialog.

Actions

  • Use one clear primary action.
  • Provide Cancel when dismissal is valid.
  • Distinguish destructive actions clearly.
  • Avoid multiple competing primary actions.
  • Prevent accidental destructive confirmation.

Behavior

  • Opening and closing are controlled by the bound `visible` state.
  • The close button is shown when `closable` is enabled.
  • Escape closes the dialog when `closeOnEscape` is enabled.
  • Backdrop click only closes when `dismissableMask` is enabled.
  • Background scrolling is blocked when `blockScroll` is enabled.
  • Maximization is available when `maximizable` is enabled.
  • Set `dismissableMask` carefully for destructive flows.
  • Avoid nested dialogs when a drawer, page, or inline pattern is better suited.

Keyboard and Focus

  • Initial focus goes into the dialog when it opens because focus-on-show is enabled by default.
  • Tab and Shift+Tab remain trapped inside the dialog when focus trapping is enabled.
  • Escape closes the dialog when supported by the current configuration.
  • Focus returns to the trigger after closing in this page.
  • Visible focus states are preserved through the existing design system tokens.
  • Tab order follows the dialog header, content, and footer controls.

Responsive Behavior

  • Desktop: wider modal content can use a fixed content width.
  • Tablet: breakpoints reduce the dialog width.
  • Mobile: the overlay becomes narrow enough to stay within the viewport.

Accessibility

  • The dialog needs a clear accessible name via its title.
  • The title is associated with the dialog by the component's aria labeling.
  • Buttons use meaningful labels.
  • Keyboard operation is supported through focus trapping and Escape handling.
  • Screen-reader context should make the dialog purpose obvious.
  • Focus visibility should remain obvious in all theme modes.
  • Avoid dialogs without a clear purpose.

Design Tokens

  • Surface/background: Graphwise surface and content background tokens.
  • Text: Graphwise text and muted text tokens.
  • Border: Graphwise border tokens.
  • Shadow: existing Graphwise elevation/shadow tokens where used.
  • Backdrop: Graphwise overlay and neutral surface tokens.
  • Spacing: Graphwise spacing scale.
  • Border radius: Graphwise radius tokens.
  • Actions: Graphwise primary, secondary, and destructive action tokens.
